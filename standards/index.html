Our standards

Useful work. Clear boundaries. Evidence you can inspect.

These are the design principles we propose for the service we are building. Each needs to be made concrete and tested within a customer’s scope. They are not a certification or a guarantee of error-free operation.

Proposed principles

  1. Make the coverage clear.

    An owner needs to know which work, sources and responsibilities the agent covers. A missing connection or unread source belongs in the operating picture. “No issue found” is meaningful only when the relevant information was actually checked.

  2. Bring the context with the recommendation.

    A decision should arrive with the reason it matters, the evidence used, the uncertainties that remain and the proposed action. People should be able to question the recommendation without reconstructing the entire situation.

  3. Agree the authority before the action.

    Access and action-taking should fit the job. Suitable routine work can have standing instructions; decisions beyond that boundary need the appropriate person. The permission model should be tested against realistic situations.

  4. Check what happened next.

    Drafting, sending, receiving a reply and confirming an outcome are different stages. The completion record should show which stage was reached and the evidence behind it. Work that is still waiting should stay visible.

  5. Turn corrections into better practice.

    A correction can reveal a missing instruction, poor source information or a workflow that needs redesign. Record the reason, test the change and check whether the same problem returns. A preference should become a standing rule only when that is what the owner intends.

  6. Count the effort we ask of you.

    The agent should help reduce the owner’s operating burden. Review time, interruptions, corrections and work shifted onto the team all belong in the evaluation. More activity is useful only when it contributes to a better outcome.

Calculate the attention returned.

For comparable work:

Net owner time returned = baseline owner time − pilot owner time.

Pilot owner time includes reviews, approvals, corrections and remaining manual steps. Keep one-time setup visible separately; include it when assessing the full trial. If the volume changes, compare time per comparable item and state the difference. Do not extrapolate a small sample into a guaranteed weekly saving.

Record team effort alongside owner time so the evaluation shows when work has merely moved to someone else. Look at completion quality and unresolved issues too. Faster work that produces a poorer outcome may not be progress.

Ask the owner one practical question.

“What did you stop having to remember or check this week?”

Write down the specific examples and anything that still occupied attention. This adds useful context to the time record; it does not replace it.

Decide what changes next.

Choose whether to continue, improve the workflow, expand the tested scope or pause it. State why. If the evidence is mixed, record the uncertainty and the next test.

Questions about the boundaries.

Does “managed” mean it will never make mistakes?

No. Management should provide a way to detect problems, contain the impact and improve the work. The relevant controls and responsibilities need to be agreed and verified for the engagement.

Will every update need my approval?

The intended approach is to distinguish routine work covered by standing instructions from decisions needing your judgment. The right balance depends on risk, scope and demonstrated performance.

What about confidential business information?

Before live access, the engagement needs clear arrangements for which information is used, who and which services can access it, how it is handled and how access ends. Those details depend on the implementation and must be settled before the work begins.

Can we stop or change a workflow?

The agreed operating process should identify who can pause work, how to revoke access and how pending work will be handled. That control needs to be tested as part of readiness for live use.
